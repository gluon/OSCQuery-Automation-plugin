# Spike, Phase 1: the formats shipped first (VST3 and AU)

**Final, 2026-11-08** (begun 2026-11-04). REAPER measured by script on Windows and on the Mac mini;
Samplitude, Live, Bitwig and GarageBand by the author with
[`phase1-checklist.md`](phase1-checklist.md). The spike is deleted; its code stays in the
history at commit `aaac2c4` (`spikes/phase1_formats/`).

## Verdict

**Pass, with two amendments to the PRD proposed** (see *For the author*).

1. **VST3 rename: works in every host but one.** Samplitude Suite 2026 (build 26215), Live
   12.4.16 and Bitwig 6.1.4 follow `kParamTitlesChanged` at once on lanes already drawn, during
   playback too, on Windows and (Live, Bitwig) on the Mac mini. REAPER (7.84 Windows, 7.80/7.85
   macOS) renames the parameter at once but leaves a lane already drawn under its old title until
   the project is reopened or the plugin is set offline and online; a lane drawn after a bind
   takes the current name.
2. **No host loses automation through bind, unbind or rebind**, provided slots are never hidden.
   Automation follows the slot's stable ID, so after a rebind a curve drawn for one target drives
   the next; in REAPER, under the old title. The plugin's own editor is where the truth is shown.
3. **AU cannot hide a slot without cost.** AUv2 has no hidden flag: the PRD's
   `kAudioUnitParameterFlag_IsHidden` is not in the macOS 15 SDK. The one means AUv2 has, leaving
   the slot out of `kAudioUnitProperty_ParameterList`, makes REAPER delete the slot's lane and
   points on unbind, and makes GarageBand never offer a slot that was hidden when the plugin
   loaded (which, on reopening a session, is every slot). With hiding off, both behave as VST3:
   REAPER keeps every lane and point, and GarageBand follows renames during playback and shows
   the AU clumps as groups.
4. **Validation passes:** pluginval at strictness 5 on the VST3 on Windows and macOS; auval on
   the AU on the Mac mini.
5. **On Apple silicon an AU must be signed as a bundle to register.** JUCE's CMake under Ninja
   leaves bundles linker-signed only, and the AU registrar ignored the spike until
   `codesign --force --deep --sign -` sealed it. The unsigned AU that CI uploads has the same gap.
6. **Five plugin IDs:** already written into the PRD (*Host parameter model per format*,
   Decisions, 2026-11-04), as the phase's done-when asks.

## What was built

`spikes/phase1_formats/` (deleted; see the commit above), a CMake project of its own:

- **"OQA Spike 8"** (Pix et Bel, `PxBl`, plugin code `Qsp8`): eight normalised float slots with
  stable IDs `slot1`…`slot8`, renamed at runtime through
  `updateHostDisplay (ChangeDetails().withParameterInfoChanged (true))`, named `(unbound)` while
  unbound, in two parameter groups "Device A" (slots 1–4) and "Device B" (5–8). Bound from its
  editor or from a command file a script writes. Version 0.0.2 added a switch, the file
  `~/.oqa-spike-phase1/no-hide`, to turn AU hiding off.
- **`juce-au-ishidden.patch`**, applied to a copy of the pinned JUCE in the spike's build folder:
  `AudioProcessorParameter::isHidden()`, read by the AU wrapper, which leaves a hidden parameter
  out of `kAudioUnitProperty_ParameterList` and marks it `ExpertMode`. Generated byte-exact: the
  three files it touches are stored CRLF in JUCE's own repository.
- **`reaper/phase1-bench.lua`**: for VST3, draws lanes on unbound slots, then binds, renames
  during playback, binds all, unbinds, rebinds to another target, makes a lane after a bind,
  re-applies a lane's state chunk, sets the plugin offline and online, saves and reopens. For AU,
  binds all first, draws lanes, renames during playback, then unbinds and rebinds slots under
  them. Each lane is logged with the parameter REAPER attaches it to. REAPER is started with
  `-cfgfile` on a copy of the user's `reaper.ini`, so the real one is never written. The same
  sequence can drive the real plugin once it can be bound without its editor (devplan Phase 6).

## What JUCE 9.0.5 does, read from its source

| Format | On `parameterInfoChanged` | Hidden | Groups |
| --- | --- | --- | --- |
| VST3 | `restartComponent (kParamTitlesChanged)` when a title changed (`juce_audio_plugin_client_VST3.cpp:1507`) | nothing in VST3 | VST3 units |
| AU | `PropertyChanged` on `ParameterList` and `ParameterInfo` (`juce_audio_plugin_client_AU_1.mm:2046`) | never set; unnamed parameters get `NonRealTime`; AUv2 has no hidden flag to set | clump ID = index of the group, fixed at construction (`:1091`) |

So an AU clump per *device* (devplan Phase 7) cannot follow a rebind through JUCE's parameter
groups: the clump is a property of the slot, not of what it is bound to.

Checked and ruled out, Samplitude build 26015: dragging an automation handle during playback moved

## For the author: what this changes in the PRD

1. **AU hidden slots.** The Binding model rule ("hidden where the format allows (CLAP
   `is_hidden`, AU `kAudioUnitParameterFlag_IsHidden`)") and the format table's AU column name a
   flag AUv2 does not have, and the one means AUv2 has loses automation in REAPER and the slots
   themselves in GarageBand. **Proposed:** AU behaves as VST3, unbound slots named `(unbound)` and
   never hidden; CLAP's `is_hidden` is untouched. The rule is in a section `CLAUDE.md` copies
   verbatim, so the change is made in the PRD and copied.
2. **The format table's rename cells.** VST3, "Reaper honours it, others inconsistently", is the
   wrong way round on today's hosts: Samplitude 26215, Live 12.4.16 and Bitwig 6.1.4 follow on
   lanes already drawn, during playback too; REAPER renames the parameter only. AU, "Logic
   partial", is unmeasured for Logic; GarageBand follows, REAPER as for VST3.
3. **Stale lanes drive the wrong target silently**, in every host; a REAPER user's one-step fix
   for the title is offline/online. Whether the plugin can refresh REAPER's titles itself (REAPER
   exposes its API to VST3 plugins) is a question for Phase 3.
4. **The plugin needs the network in sandboxed AU hosts.** GarageBand asks the user to lower its
   security to load an AU that declares file or network access, and the real plugin cannot work
   without the network. Logic sandboxes AUs the same way; Phase 7 states what the user will be
   asked, and why.
5. **Mac bundles need an ad-hoc signature over the whole bundle** from the first build a host is
   meant to load: a post-build `codesign --force --deep --sign -` for the plugin targets (Phase 3,
   or now in CI), real signing in Phase 7.

## clap-juce-extensions on JUCE 9.0.5 (information only)

Cloned at `7adee3a1` (2026-10-06) into `build/` and built with its own example CMake, CPM pointed
at the pinned JUCE 9.0.5 (`-DCPM_JUCE_SOURCE`), C++20: **`GainPlugin_CLAP` builds and links on
Windows with MSVC (VS 2026), no errors and no warnings.** Its wrapper already has a branch for
JUCE 8.0.11's `juce_audio_processors_headless` split. Not loaded in a host, not tried on macOS or
Linux. It stays out of the build, as decided; its source is what Phase 5b reads for embedding a
JUCE editor in a CLAP window.
